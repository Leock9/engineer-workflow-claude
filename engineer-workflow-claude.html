engineer-workflow-claude

Código com disciplina. Agentes com propósito.

Um pipeline multi-agente e spec-first sobre o Claude Code —
transformando linguagem natural em código revisado e confiável.

o problema

Um modelo. Responsabilidades demais.

sem estrutura
  • Detecção, design, implementação e revisão no mesmo prompt
  • Contexto enorme, foco zero
  • Sem gate: o código errado é escrito primeiro
  • Review pós-fato, se rolar
  • Decisão arquitetural invisível
com o workflow
  • Cada agente tem uma função específica e contrato definido
  • Contexto condensado ≤ 20 linhas por repasse
  • Spec aprovada antes de qualquer linha de código
  • 6 revisores em paralelo, consolidados
  • Humano no loop nas decisões críticas

/coordinator — fluxo

Spec aprovada antes do código.

1

Detecção Haiku

Detector identifica linguagem, runtime, bibliotecas e convenções do projeto

2

Arquitetura STOP

Architect avalia opções com tradeoffs → dev aprova antes de continuar

3

Gate da Spec BLOQUEIO

Pipeline travado se não houver spec aprovada — não opcional

4

Implementação Sonnet

Implementer escreve código de acordo com spec + decisão arquitetural

5

Revisão Paralela → Consolidação

Build + testes antes da revisão (máx. 1 ciclo de correção) → 5 revisores em paralelo → ReviewCoordinator → spec marcada como implemented se sem blockers

princípios de design

Rigor por design, não por acidente.

Spec-first

O /coordinator é bloqueado sem spec aprovada. O gate não é opcional — evita construir a coisa errada.

Humano no loop

Arquitetura e spec exigem sign-off explícito do dev. Nenhuma decisão crítica é tomada sem aprovação.

Disciplina de custo

Nenhum agente recebe output bruto. Cada repasse é condensado em ≤ 20 linhas. Independentes rodam em paralelo.

Crítico, não complacente

"Funciona" não é motivo para omitir um finding. Os agentes sinalizam problemas reais, inclusive em código produtivo.

Separação de responsabilidades

Implementer não revisa. Reviewer não implementa. Architect não escreve código. Cada um no seu papel.

Não é um framework

É uma camada de processo. Não substitui o dev — traz ordem, rigor e consistência ao uso do Claude Code.

economia de tokens — estimativas aproximadas

Contexto cirúrgico. Custo controlado.

✗ uso tradicional
Contexto inteiro em todo prompt
Prompt monolítico com codebase + histórico + instruções: ~8.000–20.000 tokens por chamada
Output bruto repassado entre etapas
Resposta completa vira input do próximo prompt — contexto acumula +300–600 tokens por handoff
Modelo pesado para tudo
Sonnet para classificar manifests e deduplgar findings: custo até 5× maior que Haiku nas mesmas tarefas
Revisão em série
4 revisores sequenciais: latência ~4× maior, cada um carregando o contexto do anterior
vs
✓ com o workflow
Repasse condensado ≤ 20 linhas
Contrato de entrada por agente: ~400–600 tokens — redução de ~90% por handoff
Síntese obrigatória entre etapas
Contexto não acumula. Cada agente começa limpo — economia estimada de 2.000–8.000 tokens por ciclo completo
Haiku onde Haiku basta
5 de 21 agentes rodam em Haiku — ~60–80% de redução de custo nessas chamadas específicas
Revisores em paralelo
Mesmo volume de tokens, latência de 1 revisor — ~75% menos tempo de espera na etapa de revisão
boas práticas adotadas

Disciplina de contexto.

✂️

Contratos de entrada definidos

Cada agente tem um contrato explícito de input. Nenhum agente recebe mais do que precisa para cumprir sua função.

zero over-fetching
⚡

Haiku para o estrutural

Detector, CodeExplorer, EvidenceParser, LogClassifier e ReviewCoordinator usam Haiku — tarefas de classificação e inventário não precisam de Sonnet.

model routing
🔀

Paralelismo onde não há dependência

Revisores sem dependência entre si rodam em paralelo. Detector + Architect no /investigate também. Latência cai, custo não escala linearmente.

parallel execution
🗜️

Condensação obrigatória entre etapas

O output de cada etapa é reduzido a ≤ 20 linhas antes de ser repassado. Nenhum agente acumula o histórico completo.

context compression
🎯

Um agente, uma responsabilidade

Evita re-processar informações já resolvidas. O Implementer não reanalisa o stack — o Detector já fez isso.

single responsibility
🚫

Gates que evitam retrabalho caro

Implementar sem spec aprovada é o maior desperdício de tokens. O gate bloqueia antes que o erro se propague por todo o pipeline.

fail fast
